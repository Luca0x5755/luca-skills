# 0005：決策日誌固定路徑只放當月，舊月份輪替進月份封存檔

Status: Accepted

日期：2026-11-23

## 脈絡

`docs/decision-log.md` 是一個只增不改的單檔。本 repo 的這份已有 43 KB，11 月一個月增加約 46 KB。代理改它之前要先讀，所以檔案越長，每次寫一行的成本越高，最後會超過 Read 單次上限。

`/domain-modeling` 和其他技能都直接指向 `docs/decision-log.md` 這個路徑。

## 決定

- `docs/decision-log.md` 的路徑不變，只放當月的行。
- 換月前，把上個月的行搬到 `docs/decision-log/YYYY-MM.md`。封存檔搬出後就不再修改。
- 檢查規則是「主檔每一行的年月都相同」，不看今天的日期，免得只因為日曆換月就無故變紅。
- 每行不超過 300 字，只檢查主檔。封存檔不再修改，所以舊行自然被豁免。

## 否決的做法

- **改成目錄**（`docs/decision-log/` 底下一筆一檔）：會破壞所有指向固定路徑的技能與既有目標專案，而且一行一檔只會換來大量的小檔。
- **每個決策一份 ADR**：ADR 留給通過三項門檻的決策。把日誌等級的決策升格，會埋掉真正重要的那幾份。
- **年輪替**（GCC 的 `ChangeLog-YYYY`）：照目前速度一年約 550 KB，比單次 Read 上限大一個數量級。GCC 輪替不是為了讀取成本，它的每個年份檔都有 1.3–1.9 MB。

## 外部對照

「固定路徑放當期、舊期搬進以期間命名的封存檔」的形狀，GCC 用了二十多年，只是週期是年。以月為週期，或用「主檔每行同期」當檢查，外部沒有找到先例。

## 代價

- 每月要搬一次。重跑 /setup-skills 時會自動拆分；平時由寫入當月第一行的人先搬。
- 第一次導入時，當月已有的超長行要在同一個 PR 裡修短。

# 0001：設計稿正本可以領先 `main`，`05` 是算數 board 的唯一名單

Status: Proposed

日期：2026-11-14

## 脈絡

`frontend-spec` 原本規定 mockup 是 repo 裡一頁一檔的 `.pen`，改在功能分支上、與程式碼同一個 PR 合併，所以 `main` 永遠不描述它還沒有的 UI。

各專案已把 mockup 遷到自架 Penpot。Penpot 的設計檔沒有分支：一畫完，正本就變了，而程式碼可能很久之後才合併，PR 也可能被關掉。原本的規定做不到了。

## 決定

- **設計稿正本**是專案在 Penpot 上的那一個設計檔，可以領先 `main`。
- `docs/05_frontend_spec.md` 照舊跟著功能分支，與程式碼同一個 PR 合併。
- `05` 的頁面章節逐一列出 board 名稱，是「哪些 board 算數」的唯一名單。正本裡沒被 `05` 列名的 board 不是真相。
- board 一律命名為 `<頁名> · <狀態> · <Desktop|Mobile>`，票引用的就是這個字串。明暗模式不進名稱。
- 「已上線的 UI 長怎樣」以 `main` 上的 `05` 為準；設計稿正本只回答「版面長怎樣」。

## 被否決的做法

- **在 Penpot 內模擬分支**（功能先畫在暫存頁，合併後搬進正式頁）：搬頁全靠人記得做，PR 被關掉時還要記得清。
- **每個功能複製一份設計檔，合併後手動併回**：同樣是在沒有分支的工具上手工重造 git，而且併回沒有工具可以對帳。

## 代價

- 正本上會躺著還沒實作、甚至永遠不會實作的 board。只看 Penpot 的人分不出來，必須對照 `05`。
- `05` 的 board 名單成為承重結構：名稱打錯或漏列，票就指向不存在或不算數的畫面。
- 設計稿與某個 PR 的對應，只能靠專案在 Penpot 上存的版本回溯，repo 本身查不到。

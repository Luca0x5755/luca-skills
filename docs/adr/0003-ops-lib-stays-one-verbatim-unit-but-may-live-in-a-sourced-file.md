# 0003：ops-lib 仍是一個逐字、帶版號的單位，但不需單獨執行的腳本可改放共用檔再 source

Status: Proposed

日期：2026-11-22

取代：0002（本 ADR 轉為 Accepted 時，0002 改為 `Superseded by 0003`）

## 脈絡

0002 規定 ops-lib 逐字內嵌進每支運維腳本、禁止 `source`，理由是腳本要能在 repo 不存在的機器上單獨執行。

實際用過之後，兩個使用者都不符合這個前提：一個專案的運維腳本離不開 `docker-compose.yml`、`.env`、遷移檔，初次建置也要先有 repo；本 repo 的 `scripts/manage.sh`／`manage.ps1` 要連結的就是 repo 裡的技能。前者因此自行改成「ops-lib 原樣存成 `scripts/lib/ops-lib.sh`、各腳本 source」，技能與實作開始互相矛盾。

0002 真正擋住的是走樣（各自複製的函式各改各的），不是檔案放哪裡。走樣靠的是「逐字、只改骨架、升版號再整段同步」，與內嵌或 source 無關。

## 決定

- ops-lib 仍是一個逐字單位：區段內不准手改，要改就改骨架、升版號、同步回每個副本。
- 放法依腳本能不能單獨執行決定：
  - 必須能單獨帶走執行（單檔下載、`scp`、隨身碟）→ 內嵌，同 0002。
  - 本來就離不開 repo 的檔案 → 可以整段存成 `scripts/lib/ops-lib.sh` 再 `source`，該檔只放 ops-lib，專案專屬函式另放別的檔。
- 兩種放法都用 `grep -rn "BEGIN ops-lib"` 檢查版號一致。

## 否決的做法

- **維持 0002、把偏離當專案例外**：技能與實作長期矛盾，下一個專案會再推導一次同樣的偏離。
- **一律 source**：會丟掉真的需要單檔可攜的情境。

## 代價

- 技能要多寫一個判準（能否單獨執行），由寫腳本的人判斷。
- source 的版本多一個載入失敗點：共用檔不在時，要用 `die` 說清楚缺什麼。

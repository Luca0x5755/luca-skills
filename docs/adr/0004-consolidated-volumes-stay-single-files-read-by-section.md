# 0004：合訂本維持單檔，代理按節讀，最小一節不超過 40 KB

Status: Proposed

## 脈絡

合訂本（架構、前端）會長到代理無法整份讀：整份超過 Read 的單次上限（25k token）好幾倍，連單一節都可能超過上限。代理讀不完整份，就只能猜章節在哪，或讀到截斷版。

`/to-architecture` 規定合訂本不拆。capability 檔的 `## 規格章節`、能力標記檢查、票裡的章節引用，以及已安裝的目標專案，都假設「一份合訂本一個路徑」。

## 決定

- 合訂本維持單檔，不拆成每章一檔。
- 最小一節（沒有子標題的那一層）不超過 40 KB。超過就在同一檔裡往下切標題。由 /setup-skills 安裝的 CI 檢查強制，表格和程式碼區塊不豁免。
- 每份大型**現行文件**的第一行寫讀法：不要整份讀，先查 capability 檔的 `## 規格章節`，grep 標題行號，只讀那一段。檢查只驗證這一行存在。

40 KB 約 1.2 萬 token，比單次 Read 上限低一倍，留了餘裕。

## 否決的做法

- **每章一檔**：會破壞 capability 檔的路徑、能力標記檢查、票的章節引用，以及既有目標專案。
- **只靠讀法、不設節上限**：讀法只告訴代理讀哪一段，那一段本身仍可能超過單次 Read 上限。

## 外部對照

外部的超大單一原始檔（WHATWG HTML 約 8 MB、ECMA-262 約 3 MB）也不拆，但兩者都沒有節大小規則，也沒有讀法。WHATWG 有二十多節超過 40 KB。它們不需要這些規則，因為建置工具會把原始檔切成多頁，讀者讀的是切好的頁面。我們沒有建置層，代理直接讀原始檔，所以用節上限和第一行讀法代替切頁。外部沒有這兩條的先例。

## 代價

- 第一次套用時，超過 40 KB 的節要在同一個 PR 裡切開。
- 切出的新標題如果承載能力，要同步 capability 檔的 `## 規格章節`。

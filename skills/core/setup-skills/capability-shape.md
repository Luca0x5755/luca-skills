## Capability 檔形狀

`docs/capabilities/<name>.md` 一個能力一檔，記錄系統**現在**做什麼；需求的來歷歸 PRD 與規格。`<name>` 是檔名主幹，也就是合訂本標題 `（能力：<name>）` 裡的名字。檔案依序由五部分組成：

1. **現況** — 開頭一段：這個能力現在做什麼。
2. **服務對象** — 誰用它、用來完成什麼。
3. **`## 規格章節`** — 合訂本裡每個帶本能力標記的標題各一行，格式 `` - `<合訂本路徑>` <標題全文去掉標記> ``，合訂本路徑是 `docs/03_architecture_design.md` 或 `docs/05_frontend_spec.md`。標題與這份清單雙向一致：任一方向缺漏，真相地圖檢查即報紅。
4. **`## Promises`** — 本能力的承諾，一行一個，格式 `<ID> — <行為>`。退役的承諾保留原行，改成 `<ID> — retired：<理由>`；ID 永不重發。行首的 `- ` 可有可無。合訂本只引用 ID，承諾內文只住這裡。
5. **`## 驗證`**（選用）— 驗證這個能力的測試或腳本，一行一個。

建立或修改 capability 檔的技能都照這個形狀寫，不另立格式。
